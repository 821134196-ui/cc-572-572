# 中学实验室玻璃器皿领用与破损登记系统

老师按课程给学生组**配发**器皿，实验结束后**逐件扫码核对归还**；清洗质检员做入库前检查与清洗；
管理员处理破损免赔审核、核销与盘点。每件器皿有**独立编号和独立柜位**，使用、清洗、破损、盘点履历全程可溯。

## 一条本地命令启动

```bash
./run.sh
```

脚本会自动安装依赖、初始化 SQLite 并写入演示种子数据，然后启动服务。
浏览器打开 <http://127.0.0.1:8000>（可用 `PORT=8001 ./run.sh` 改端口）。

```bash
python3 demo.py     # 端到端演示（自动重建库、临时起服务、跑完自动关闭）
```

## 技术栈

- 后端：Python + FastAPI + SQLAlchemy 2 + SQLite（`backend/`）
- 前端：Vue 3（本地化单文件，无需 npm 构建，`frontend/`）
- 照片：本地磁盘 `uploads/`（≤8MB）
- 清洗设备：`backend/device.py` 内存模拟（任务号 `WASH-xxxxx`，约 6 秒完成程序）

## 核心业务规则（后端强制校验）

1. **一件不借两组**：配发时任一部件非「可借」即整单 409 拒绝；套件扫任一部件自动带出整套。
2. **套件逐件核对**：套件父件 + 每个部件都是独立实物、独立编号柜位；缺件精确提示到部件名，
   结单时未逐件登记（含登记为「缺失」）不允许按整套数量认定还齐。
3. **归还只记一次**：重复扫码同一编号返回 409，保留首次登记，不覆盖、不入第二笔。
4. **合格才回库**：归还「完整」→ 待目检 → 待清洗 → 模拟设备清洗 → 质检员判定合格才回到可借库存。
5. **破损追溯上课**：清洗/目检后才发现破损，按最近一次领用记录自动关联到课程、班级节次与学生组。
6. **免赔回避**：任课老师只能提交申请；本节任课老师自行审核 403，清洗质检员也无权；
   须由非本节任课老师或管理员审核。
7. **盘点不改账**：建单时冻结系统状态快照；账实不符保留为盘亏/盘盈差异并写明查明结果，
   可另登记缺失并追溯上课，但**绝不回改领用/归还记录**。
8. **岗位边界**：配发归还=老师/管理员；检查清洗=清洗质检员/管理员；盘点核销=管理员。

## 页面

- **工作台**：各状态实物数量、进行中领用单、待审核免赔、待查明盘亏。
- **柜位查询**：按编号/状态/柜位查实物；点开看套件部件在位情况与完整履历时间线。
- **领用归还**：选课选组扫码配发；领用单内逐件扫码登记完整/待清洗/裂纹/缺失，套件缺件红框提示。
- **检查清洗**：三段队列（待目检 / 待清洗 / 设备处理中），设备就绪后判定合格或破损。
- **破损免赔**：登记、照片上传、免赔申请与审核（审核人、意见、时间留痕）、管理员核销。
- **盘点**：建单冻结快照、扫码记相符、台账外编号记盘盈、差异查明、关闭留痕。

## 目录

```
backend/
  database.py   # SQLite engine/session，data/、uploads/ 自动创建
  models.py     # 用户/品种/套件部件/实物/课程/学生组/领用单/逐件行/破损/清洗/盘点
  schemas.py    # Pydantic 模型
  device.py     # 模拟清洗设备接口（submit/fetch，任务状态机）
  main.py       # FastAPI 全部接口、权限依赖、状态流转
  seed.py       # 演示种子数据
frontend/       # index.html + styles.css + app.js（Vue 3 全局构建，CDN 文件已下载到 vendor/）
demo.py         # 七个场景的端到端自动演示
run.sh          # 一条命令：装依赖 → 重建种子库 → 启动
```
